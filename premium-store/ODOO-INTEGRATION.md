# مجالس العرب — متطلبات تشغيل الربط الحقيقي مع Odoo

## الحالة الحالية (21 نوفمبر 2026)
- `index.html` متجر معاينة. ليست فيه صلاحية مؤكدة لتحصيل الأموال أو قبول طلب حقيقي.
- `storefront-api.js` عميل اختياري لبوابة **خلفية** (Backend) منفصلة. جميع المفاتيح `enabled`, `catalogEnabled`, `checkoutEnabled` معطلة افتراضيًا.
- لا تضع بيانات الدخول إلى Odoo أو API keys أو بيانات بوابات الدفع داخل HTML أو JavaScript المنشور للعامة.
- لا تعدّل حقول `enabled` قبل إعداد خادم API والتحقق من HTTPS، الهوية، الفروع، صلاحيات الوصول والاختبارات.

## إعدادات البيئة العامة (غير سرية فقط)
تُضبط قبل تحميل `storefront-api.js`:
```html
<script>
window.MAJALIS_STORE_CONFIG = {
  enabled: false,
  apiBase: "https://your-own-gateway.example/",
  catalogEnabled: false,
  checkoutEnabled: false
};
</script>
```
هذا مثال إعداد فقط؛ الرابط ليس خدمة قائمة. تحتفظ بوابة API الخلفية بكل أسرار Odoo والدفع.

## عقد API المطلوب من الخادم
1. `GET /api/storefront/v1/catalog`
   - الرد: `{ "source":"odoo", "approved":true, "currency":"SAR", "revision":"...", "products":[{"id":1,"name":"...","category":"الفطور والعشاء","price":20,"available":true,"image_url":"https://...","options":[]}] }`.
   - المعرف رقمي ثابت وفريد، السعر موجب أو صفر وبيانات الفئات من Odoo؛ لا تعتمد على أسماء أو أسعار تجريبية.
   - الصور الخارجية عبر HTTPS ويُفضّل استخدام نطاق صور معتمد.
2. `GET /api/storefront/v1/capabilities`
   - الرد: `{ "catalog":true, "orders":false, "payment":false }` حتى إكمال اختبارات التشغيل.
3. `POST /api/storefront/v1/quote`
   - يستقبل `items` (معرف الصنف والكمية والاختيارات) والفرع/التوصيل فقط بعد تحقق المستخدم.
   - **يعيد حساب الأسعار والضرائب والتوصيل والخصومات من قاعدة بيانات Odoo بالخادم**، ويتحقق من الأصناف والمخزون ومنطقة التوصيل.
   - يعيد `quote_id` مؤقتًا صالحًا لمدة محدودة والإجمالي النهائي.
4. `POST /api/storefront/v1/orders`
   - لا يفعّل قبل المصادقة وCSRF / الحماية ضد الإساءة وإعادة الإرسال.
   - يستقبل `quote_id` ومعرّف `Idempotency-Key` لمنع التكرار.
   - ينشئ الطلب بصورة ذرية في Odoo ويرجع `order_id` و`checkout_url` من مزود دفع معتمد عندما يلزم.
   - لا تُعتمد حالة **مدفوع** من عودة المتصفح؛ تؤكد من Webhook موقع/موقّع من مزود الدفع.
   - تتطلب الطلبات النقدية/الاستلام سياسة مؤكدة من الإدارة وقواعد حالة الطلب.

## متطلبات العميل والتشغيل
- عنوان Odoo الفعلي، نسخته وقواعد بيانات الاختبار والإنتاج وصلاحيات حساب خدمة محدود.
- القائمة المعتمدة، كود كل صنف، الضرائب، أسعار الفروع، الصور، الأحجام، الإضافات، الحساسية، التوفر ومواعيد البيع.
- الفروع وساعات العمل ونطاقات ورسوم التوصيل والاستلام وحدود الطلب الدنيا.
- مزود الدفع السعودي المتعاقد معه، حسابه التجاري، المفاتيح المحمية، سياسات الاسترجاع والمرتجعات.
- سياسة إكمال الطلب والإلغاء وتعطيل الصنف والتعديل وإشعارات العميل.
- آلية ربط أوامر المتجر بـ POS / Sale Orders / KDS (تُحدد بناءً على تطبيقات Odoo الفعلية).
- اختبار شامل قبل تغيير `capabilities.orders` و`capabilities.payment` إلى `true`.
